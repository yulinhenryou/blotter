# M0 plan — Monorepo skeleton and CI

Status: **planned** (not started). Acceptance criteria: `ROADMAP.md` → M0.

M0 contains no feature code. Its purpose is that every later change lands in a repository where
all three layers build, test and lint the same way locally and in CI, and where the Rust → Python →
web path is proven end to end by one trivial value: the engine version.

### Task 1 — Repository foundation

Files: `.gitignore` (Rust `target/`, Python `.venv/`, `__pycache__/`, `*.so`, Node `node_modules/`,
`dist/`, local SQLite files), `.editorconfig`, `LICENSE-MIT` and `LICENSE-APACHE` (verbatim

```json

```

Verify: `git init -b main`; first commit contains only docs + these files.

### Task 2 — Rust workspace

Files:
- `Cargo.toml` — `[workspace]` with `members = ["crates/*"]`, `resolver = "3"`;
  `[workspace.package]` (edition, `license = "MIT OR Apache-2.0"`, `publish = false`); `[workspace.dependencies]` for
  shared versions; `[workspace.lints]` shared by all crates.
- `rust-toolchain.toml`.
- `crates/cards/` and `crates/solver/` — library crates, each with a `lib.rs` that exposes a
  `version()`-style constant and one unit test. `solver` depends on `cards` (proves the
  intra-workspace dependency).
- `crates/solver/benches/placeholder.rs` — criterion bench (`harness = false`).
- `deny.toml` — allow-list of licenses compatible with MIT OR Apache-2.0 distribution;
  copyleft licenses (GPL, LGPL, AGPL) denied; `cargo deny
  check licenses` passes.

Verify: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo test --workspace`, `cargo bench --no-run`, `cargo deny check licenses`.

Teaching notes: what a crate, a package and a workspace are; `lib` vs `bin` vs `cdylib`; editions;
how Cargo resolves the `path` dependency from `solver` to `cards`; `#[cfg(test)]` modules; what
`&'static str` means for a version string compiled into the binary (`env!("CARGO_PKG_VERSION")`).

### Task 3 — Python bindings crate

Files: `crates/bindings/Cargo.toml` (`crate-type = ["cdylib"]`, depends on `pyo3` and `solver`),
`crates/bindings/src/lib.rs` with a `#[pymodule]` named `_engine` exposing `version()`.

Points to verify during the task (not assumed):
- PyO3's `extension-module` feature must be enabled by maturin only (configured in
  `pyproject.toml`), not unconditionally in `Cargo.toml`, so that `cargo clippy` / `cargo test` on
  the workspace still link. If `cargo test --workspace` still fails to link for `bindings`, exclude
  it from `cargo test` (it has no Rust tests; it is tested from Python).
- The exact module-function signature for the PyO3 version we pin (it has changed across
  versions).

Teaching notes: what the `#[pyfunction]` / `#[pymodule]` macros generate; `PyResult<T>` and the
`?` operator; the GIL token and what the `'py` / `'_` lifetimes on `Bound<'py, PyModule>` express
(borrowing tied to holding the GIL); why `bindings` holds no logic.

### Task 4 — Python package

Files:
- `python/pyproject.toml` — `[build-system]` maturin; `[project]` name (= project name, lower
  case), `license = "MIT OR Apache-2.0"`, `requires-python`, dependencies `fastapi`, `uvicorn`; `[dependency-groups] dev = [pytest,
  hypothesis, httpx, ruff, mypy]`; `[tool.maturin]` with `manifest-path =
  "../crates/bindings/Cargo.toml"`, `python-source = "src"`, `module-name = "review._engine"`,
  `features = ["pyo3/extension-module"]`; `[tool.ruff]`, `[tool.mypy]` (`strict = true`),
  `[tool.pytest.ini_options]`.
- `python/.python-version`, `python/uv.lock` (generated).
- `python/src/review/__init__.py`, `py.typed`, `_project.py` (`DISPLAY_NAME`), `_engine.pyi`,
  `engine.py` (typed wrapper: `engine_version() -> str`).
- `python/src/review/api/app.py` — app factory; `GET /api/v1/health` →
  `{"status": "ok", "engine_version": "..."}`; OpenAPI title from `DISPLAY_NAME`.
- `python/tests/test_engine.py`, `python/tests/test_health.py`.
- `scripts/export_openapi.py` — writes the app's OpenAPI schema to `web/openapi.json`.

Verify: `uv sync`, `uv run ruff check`, `uv run ruff format --check`, `uv run mypy`,
`uv run pytest`; `uv run uvicorn …` serves `/api/v1/health`.

Point to verify: how uv detects that the Rust sources changed and the native module must be
rebuilt (uv `cache-keys` on `crates/**/*.rs`, or an explicit `maturin develop --uv`). The
working command goes into `DEVELOPMENT.md`.

Teaching notes: how maturin builds a wheel that contains both the Python sources and the compiled
`_engine` module; why the distribution name and the import name differ; what `mypy --strict`
demands and why the `.pyi` stub is needed for the native module.

### Task 5 — Web app

Files:
- `web/` from the Vite React + TypeScript template (`package.json` with
  `"license": "MIT OR Apache-2.0"`), then: `tsconfig` with `strict`; ESLint flat
  config; Prettier; Vitest + Testing Library + jsdom; `.nvmrc`.
- `web/vite.config.ts` — reads `../project.json` at build time: page `<title>` and a `define`
  constant for the display name; dev proxy `/api` → the local FastAPI server.
- `web/openapi.json` (committed contract) → `web/src/api/schema.d.ts` generated with
  `openapi-typescript`; `web/src/api/client.ts` thin `fetch` wrapper.
- `web/src/design/tokens.css` — first tokens: colors (light + dark), spacing scale, font stacks
  (serif headings, system UI body), `font-variant-numeric: tabular-nums` for numbers.
- `web/src/App.tsx` — shows display name, tagline and the engine version from `/api/v1/health`,
  with loading and error states.
- One component test (renders the version from a mocked response).

Verify: `npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`; manual check
with both servers running: the page shows the real engine version (AC 4).

### Task 6 — Project-name check

File: `scripts/check_project_name.py` (standard library only) plus its tests.

Behavior:
1. Read `displayName` from `project.json`.
2. Search tracked files (`git ls-files`) case-insensitively for the name.
3. Fail if it appears outside the allow-list: `CLAUDE.md`, `README.md`, `docs/VISION.md`,
   `docs/DECISIONS.md`, `project.json`, `python/pyproject.toml`,
   `python/uv.lock`, `python/src/review/_project.py`, `web/package.json`, `web/package-lock.json`.
4. Fail if the name in `pyproject.toml`, `package.json` and `_project.py` disagrees with
   `project.json`.

Update the rename checklist in `CLAUDE.md` §4 to match the final list (lock files included).

### Task 8 — CI workflows

| Workflow | Triggers (paths) | Steps |
|---|---|---|
| `rust.yml` | `crates/**`, `Cargo.*`, `rust-toolchain.toml`, `deny.toml` | toolchain from `rust-toolchain.toml`, cache, fmt, clippy `-D warnings`, test, `bench --no-run`, cargo-deny |
| `python.yml` | `python/**`, `crates/**`, `scripts/export_openapi.py` | Rust toolchain, setup uv, `uv sync --locked`, ruff check, ruff format --check, mypy, pytest, OpenAPI drift check (regenerate `web/openapi.json`, fail on diff) |
| `web.yml` | `web/**` | Node from `.nvmrc`, `npm ci`, lint, typecheck, test, build, generated-types drift check |
| `repo.yml` | all pushes | project-name check and its tests |

Runner: `ubuntu-latest` for all. macOS is covered by Henry's local runs; a macOS CI job can be
added later if platform-specific issues appear.

## 3. Risks and open questions

| Risk | Mitigation |
|---|---|
| PyO3 `extension-module` breaks `cargo test` linking | Feature enabled only through maturin; exclude `bindings` from `cargo test` if needed (Task 3) |
| Stale native module after Rust edits (tests pass against an old build) | Documented rebuild command; CI always builds from scratch |
| Vite dev server refuses to read `../project.json` | Read it in `vite.config.ts` with Node's `fs` at config time instead of importing it from app code |
| Lock files contain the project name | Explicitly in the allow-list and the rename checklist |
